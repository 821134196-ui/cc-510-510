# 养老机构呼叫与夜巡系统（演示）

把 **床位 · 床头呼叫按钮 · 当班护理员 · 夜巡计划** 关联为一体的本地化演示系统：
住户按下按钮即记录来源、时间，呼叫派给当班护理员，到床旁确认后填写处理结果；
夜巡漏检单独提醒；护理员交班时未结呼叫与待办夜巡自动转交、事件链不断。

纯 Python 标准库 + SQLite + 原生前端，**零第三方依赖**，完全离线可运行。
所有住户/员工均为虚构样本。

## 一条命令启动

```bash
python3 run.py            # 首次自动建库、播种虚构数据并生成离线/超时/漏检演示案例
# python3 run.py --reset  # 清空数据重来
# python3 run.py --demo   # 在已有数据库上追加一遍演示案例
# python3 run.py --no-demo # 只启动，不生成案例
```

启动后访问：

| 终端 | 地址 | 账号 | 说明 |
|---|---|---|---|
| 楼层屏 | http://localhost:8000/screen | 免登录 | 高对比大字、楼层床位图；呼叫位置与时间**紧邻展示**；红色报警**同时配文字** |
| 护理员手机端 | http://localhost:8000/phone | N1–N4 / `0000` | 只有**当前待办与确认动作**：接单、到床确认、处理结果、误触说明、急救结案 |
| 值班长台 | http://localhost:8000/leader | L1、L2 / `1234` | 实时呼叫派单、误触核对、夜巡、交班、统计、住户资料 |

启动时自动生成的案例：

- **按钮离线**：一楼 103房1号床 `B-103-1` 心跳中断，约 1 个监控周期内上屏提醒；
- **超时未响应**：201房1号床（15 秒提醒 / 30 秒自动急救升级）、201房2号床（启动即升级）；
- **派单后未到床**：202房1号床已派 N3，20 秒提醒 / 45 秒自动升级；
- **夜巡漏检**：一条全护床位夜巡任务超窗，以独立「夜巡漏检」提醒推送（不与呼叫混淆）。

值班长台「演示控制」可手动按按钮、断/连心跳，观察完整流程。

## 核心业务规则

- **派单单占**：一通未结束呼叫不能同时派给两人；一名护理员也不能同时持有两通未结束呼叫
  （数据库部分唯一索引 + 服务层守卫双保险，并发下也安全）。
- **响应闭环**：`待派单 → 已派单 → 已到床 → 已结案`，处理结果必填。
- **误触不可删除**：护理员必须选择原因并填写书面说明 → 转为「误触待核」→
  **值班长核对**：核实（记录保留为「误触已核实」）或驳回（恢复原状态继续处理）。
- **急救升级**：值班长/现场可手动升级；无人接单超时、派单后超时未到床、同床连续呼叫 3 次
  都会自动升级。升级后**普通结案被阻断**，只能「急救结案」；升级通知全员（楼层屏+手机）。
- **住户外出**：可登记外出/返院；外出期间按钮被按，呼叫照走但醒目标注「住户外出，请现场核实」。
- **按钮离线**：模拟心跳超时识别，独立的离线/恢复通知，提醒改用人工巡查。
- **交班不断链**：值班长见证下交班，负责人手上的呼叫改派接班人、待派单呼叫与待办夜巡转入新班次，
  每通呼叫事件链中保留「交班转交」记录；交接附件保存在本地文件 `data/attachments/`。
- **岗位权限**：护理员端只返回照护必需字段；饮食、病史、家属联系方式等敏感资料仅值班长可见；
  派单/核对/资料/统计等接口在服务端做角色校验。

## 交付视图

- **楼层床位图**：`/screen` 三层 × 8 床，实时状态色块（呼叫红、派单琥珀、到床深绿、离线灰、外出虚线）；
- **实时呼叫**：楼层屏横幅 + 值班长台「实时呼叫」+ 护理员待办；
- **夜巡任务**：值班长台可查待巡/已巡/迟巡/漏检，护理员在手机端逐床确认；
- **交班记录**：交班双方、值班长、摘要、转交呼叫/夜巡清单、附件下载；
- **响应统计**：本班呼叫数、状态分布、急救结案、误触、平均响应时长、夜巡完成情况。

配色：暖白底色 + 深绿主色，急救红仅用于急救/最高级报警；所有报警均同时有文字说明。

## 事件与存储

- SQLite 数据库：`data/carecall.db`
  - `calls`（呼叫全状态）、`events`（每通呼叫的完整事件链）、`notifications`（多通道通知）、
    `patrol_tasks`（夜巡）、`handovers`（交班）、`audit_log`（敏感操作审计）等；
- 交接附件：本地文件目录 `data/attachments/`（数据库只存元信息）；
- 模拟适配器：`app/adapters.py`（按钮心跳/按键、通知通道），真实环境可替换为 MQTT/网关 SDK；
- 后台监控：`app/monitor.py`（超时、离线、夜巡到时/漏检、自动升级）。

## 测试

```bash
python3 -m unittest discover -s/tests -v
```

覆盖：重复派发拦截、一人不能持两通、超时提醒与自动急救升级、急救后普通结案阻断、
误触必填说明与值班长核对（核实/驳回恢复）、连续呼叫升级、按钮离线只提醒一次、
夜巡到时提醒与漏检分离、岗位字段权限、交班后接班人可继续处置（不断链）、附件落本地文件。

## 目录结构

```
run.py                 一条命令启动（含演示案例生成）
app/
  config.py            阈值（秒，可用环境变量覆盖）
  db.py                SQLite 建表与连接
  domain.py            呼叫状态机/夜巡/交班/权限
  adapters.py          模拟按钮、通知适配器
  monitor.py           后台监控线程
  server.py            HTTP API + 页面服务
  seed.py              虚构样本数据
  web/                 楼层屏、手机端、值班长台页面
tests/test_system.py   领域规则 + HTTP 端到端测试
```
